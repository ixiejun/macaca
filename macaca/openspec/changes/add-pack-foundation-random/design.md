# Foundation Random Pack Design

## Context

`pack.foundation.random.v1` provides random value generation for Macaca
applications. It must support cryptographic random bytes, UUIDs, nonces, tokens,
bounded integers, deterministic test streams, and entropy diagnostics through the
canonical service runtime path.

The pack is deliberately small. Cryptographic protocols, key management,
secrets, signing, wallets, and authentication flows belong to specialized packs
or services. This pack supplies safe randomness primitives and evidence that the
randomness source was available and policy-approved.

## Supplier API Comparison

| Source API family | Relevant concepts | Macaca abstraction |
| --- | --- | --- |
| Web Crypto | `getRandomValues`, `randomUUID`, secure-context availability | random bytes, UUID v4, provider availability, secure-context diagnostics |
| Node.js Crypto | `randomBytes`, `randomFill`, `randomInt`, `randomUUID`, sync/async variants | bytes, fill, bounded int, UUID, async command results, provider capability report |
| Apple Security | `SecRandomCopyBytes`, Randomization Services | cryptographic byte generation, OS RNG provider, structured provider failure |
| Android/Java SecureRandom | provider-backed RNG, `getInstanceStrong`, algorithm/provider selection | strength class, provider class, strong RNG diagnostics, no provider object leakage |
| POSIX/system RNG | `getrandom`, `/dev/urandom`, blocking/entropy availability | entropy health, blocked/unavailable diagnostics, max byte limits, resource policy |

Design conclusion: Macaca should expose a provider-neutral RNG contract with
explicit strength and deterministic-test separation. It must not expose raw RNG
provider objects or allow app-selected insecure algorithms.

## Goals

- Provide cryptographic random bytes, random fill, bounded random integers, UUID
  v4, nonce, token, deterministic test stream, deterministic stream bytes, entropy
  health, and provider capability commands.
- Separate production cryptographic randomness from deterministic test/replay
  randomness.
- Support max byte limits, rate limits, token alphabet bounds, and integer range
  validation.
- Support mock/unavailable providers for deterministic tests.
- Emit sanitized trace/audit evidence without logging generated random values.

## Non-Goals

- No key generation, signing, encryption, password hashing, or secret storage.
- No application-selected insecure pseudo-random algorithms.
- No direct access to `SecureRandom`, OpenSSL RNG, Web Crypto, SecRandom, or
  system RNG provider objects.
- No logging of generated bytes, tokens, UUIDs, nonces, seeds, or raw provider
  payloads.
- No deterministic seeded streams outside policy-approved test or replay
  contexts.

## Ownership And Boundaries

- Pack id: `pack.foundation.random.v1`.
- Family: `foundation`.
- Service owner: random system service.
- Provider examples: host CSPRNG provider, browser crypto provider, deterministic
  test provider, unavailable provider.
- SDK surface: `sdk.packs.foundation.random`.
- Command namespace: `random.*`.
- Microkernel ownership: identity, policy facade, service-call evidence,
  trace/audit primitives only.
- Application framework ownership: manifest declaration, app-scoped permission
  declarations, effective capability projection, WASM ABI import exposure.
- Runtime-host ownership: provider registration, host RNG adapter, decorators,
  entropy health snapshots, unavailable provider composition.

## Command Surface

| Command | Supplier analogs | DTO notes | Side effects |
| --- | --- | --- | --- |
| `random.bytes` | Web Crypto `getRandomValues`, Node `randomBytes`, SecRandom | byte length, strength class, max bytes, purpose label | No persistent side effect |
| `random.fill` | Node `randomFill`, Web Crypto fill | buffer/artifact ref, range, strength class | Mutates buffer/artifact |
| `random.integer` | Node `randomInt` | min/max exclusive/inclusive mode, bias-free requirement | No |
| `random.uuid_v4` | Web/Node `randomUUID` | count, entropy cache policy, lowercase/canonical format | No |
| `random.nonce` | protocol nonce generation | byte length, encoding, purpose, uniqueness window | No |
| `random.token` | token/id generation | byte length or char length, alphabet class, encoding, collision policy | No |
| `random.test_stream_create` | seeded deterministic RNG for tests | seed reference, replay id, algorithm id, policy context | Creates test stream |
| `random.test_stream_bytes` | deterministic stream read | stream id, byte length, expected position | Advances test stream |
| `random.entropy_health` | RNG diagnostics | provider class, blocking state, max bytes, strength support | No |
| `random.provider_capabilities` | provider inspection | supported commands, limits, deterministic support | No |

## DTO Model

Core DTOs:

- `RandomStrength`: cryptographic, strong_when_available, deterministic_test.
- `RandomPurpose`: session_id, nonce, idempotency_key, temporary_name, test_data,
  provider_protocol, generic.
- `RandomBytesRequest`: length, strength, purpose, max blocking duration,
  replay policy, trace binding.
- `RandomIntegerRequest`: min, max, inclusive mode, bias-free requirement.
- `RandomTokenSpec`: length, alphabet class, encoding, collision warning policy.
- `RandomUuidSpec`: version, canonical formatting, count, entropy cache policy.
- `RandomSeedRef`: opaque seed reference for test/replay contexts; raw seeds are
  not logged.
- `RandomStreamRef`: deterministic stream id, algorithm id, position, trace binding.
- `RandomHealth`: provider class, entropy available, blocking risk, max bytes,
  deterministic support, unavailable reasons.
- `RandomError`: denied, invalid_length, invalid_range, invalid_alphabet,
  unsupported, deterministic_not_allowed, quota_exceeded, entropy_unavailable,
  blocked, unavailable, provider_failure.

## Permission And Policy Model

Permission scopes:

- `random.generate`
- `random.identifier`
- `random.token`
- `random.nonce`
- `random.health`
- `random.test_seed`

Policy rules:

- Production commands require cryptographic or strong provider capability.
- Deterministic test streams require explicit test/replay context and are denied
  in production application execution.
- Generated values are never logged; audit records include length, purpose,
  strength, provider class, and bounded result metadata only.
- Maximum byte length, maximum token count, and rate limits are enforced before
  provider calls.
- Bounded integers must use bias-free generation or return unsupported.
- Entropy blocked/unavailable states must return structured diagnostics rather
  than falling back to insecure pseudo-randomness.

## SDK And Developer Documentation

SDK discovery returns command schemas, supported strength classes, limits,
provider class, deterministic-test support, permission scopes, policy templates,
health, examples, docs link, and unavailable diagnostics.

Required developer guide:

- Path: `docs/developer-packs/foundation/random.md`.
- Content: cryptographic versus deterministic randomness, permissions, value
  types, command DTOs, result DTOs, errors, UUID/nonce/token guidance, integer
  bias avoidance, deterministic test streams, unavailable diagnostics, provider
  replacement, trace/audit fields, and security guidance.
- Examples: generate bytes, create UUID, generate nonce, generate token, bounded
  random integer, deterministic test stream, denied test seed in production, and
  entropy unavailable diagnostics.

## Trace, Audit, Health, Snapshot, And Replay

Required event names:

- `random_pack_declared`
- `random_pack_admission_validated`
- `random_pack_policy_decision`
- `random_pack_service_call_requested`
- `random_pack_service_call_succeeded`
- `random_pack_service_call_failed`
- `random_pack_test_stream_created`
- `random_pack_entropy_health_recorded`
- `random_pack_unavailable`

Events include pack id, service id, command name, trace id, app/session/task
identifiers, purpose, strength class, byte length or count, provider class,
latency, bounded resource counters, and bounded error code. Events must not
include generated values, raw seeds, raw provider payloads, credentials, or raw
secret material.

Health checks include provider registered state, CSPRNG availability, blocking
risk, max byte request, UUID support, random integer support, deterministic test
support, provider class, and unavailable reasons.

Snapshots include descriptor version, provider class, health, command
availability, policy template hash, rate-limit counters, deterministic stream
metadata hashes, and sanitized replay references.

## Implementation Slices

1. Contract slice: descriptor, command schemas, random DTOs, health/snapshot DTOs,
   result/error DTOs, provider capability report, stable hashes.
2. Admission slice: permission validation, deterministic-test context validation,
   length/range/alphabet validation, service mapping validation.
3. Service slice: random service trait/provider interface, unavailable provider,
   deterministic test provider, host CSPRNG provider, browser crypto bridge where
   applicable.
4. SDK slice: discovery, typed command builders, token/nonce/UUID helpers,
   deterministic test helpers, unavailable diagnostics, docs link.
5. WASM/app-runtime slice: expose only declared callable random imports through
   service runtime; no raw host RNG handles.
6. Observability slice: trace/audit events, redaction, entropy health snapshots,
   replay tests.
7. Developer-docs slice: complete `docs/developer-packs/foundation/random.md`
   and link it from catalog metadata.

## Design Patterns

- **Facade**: SDK exposes safe random helpers and command builders only.
- **Command**: every operation is a typed command/result.
- **Adapter/Bridge**: Web Crypto, Node/OpenSSL, SecRandom, SecureRandom, system
  RNG, mock, and unavailable providers adapt to one contract.
- **Strategy**: provider selection, strength policy, deterministic behavior, and
  unavailable behavior are replaceable.
- **Decorator**: trace, policy, quota, entropy health, and redaction wrap calls.
- **Specification**: length, range, alphabet, strength, and test-context rules
  are executable validators.
- **Memento**: snapshots capture health and deterministic stream positions
  without exposing generated values.

## Risks And Mitigations

- Risk: generated random values leak through logs.
  Mitigation: event schema forbids generated bytes/tokens/UUIDs/nonces and tests
  enforce redaction.
- Risk: deterministic seeded randomness is used in production.
  Mitigation: policy denies test streams outside test/replay contexts.
- Risk: provider entropy is unavailable and code falls back insecurely.
  Mitigation: unavailable/blocked diagnostics are explicit; insecure fallback is
  rejected.
- Risk: bounded integer generation introduces modulo bias.
  Mitigation: command contract requires bias-free generation or unsupported.
- Risk: app-specific token formats creep into OS code.
  Mitigation: OS exposes generic token alphabet/encoding specs only; apps own
  semantic interpretation.
